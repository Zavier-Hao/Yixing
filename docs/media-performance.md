# 首页人仔与功能 04 视频加载优化

2026-11-09，本地完成实现和限速对照验证；这些结果不代表线上服务器实测，也不包含第三方 Riot 素材的网络表现。

## 改动

- 首页骑士改为保留透明通道的 768px WebP，提前发现并设为高优先级；原 PNG 留作素材源。
- 非首屏截图仅在接近视口时赋予 src。单用原生 loading=lazy 仍可能预取数屏外大图，因此增加 IntersectionObserver 边界。
- 功能 04 改为散列命名的 H.264 / MP4，保持 1280×720、约 10 秒，24 fps；播放索引 moov 从文件末尾移到开头。海报压缩为 WebP。
- 首页不创建视频 source 请求；距视频 900px 时预热，进入视口播放，离开或后台暂停，保留手动播放/静音控件。
- Demo 图集不再被首屏 CSS 背景和 JS 同时提前加载，进入 Demo 时才解码；图集本身也重新压缩。
- 资源名带内容散列，更新不会误用旧素材；Node 静态服务为散列命名媒体设置长期缓存。生产环境由 Nginx 直出时，缓存策略仍以 Nginx 配置为准。

| 素材 | 原大小 | 优化后 | 减少 |
|---|---:|---:|---:|
| 首页骑士 | 1,366,529 B | 110,488 B | 91.9% |
| 魔法书形象 | 1,357,161 B | 89,418 B | 93.4% |
| 功能 04 视频 | 4,139,017 B | 1,790,973 B | 56.7% |
| 视频海报 | 260,968 B | 66,760 B | 74.4% |

## 对照结果

Windows Edge 无头浏览器，1440×900；本地 HTTP 相同服务实现，Chrome DevTools Protocol 限制为 **1.6 Mbps 下载、80ms 延迟、CPU 4 倍降速、禁用缓存**。两边采用相同的外部 HTTPS 请求拦截设置，以隔离站内资源优化效果。每轮使用新浏览器上下文。

人仔指标：导航开始到首页骑士图解码并经过一个动画帧。视频指标：骑士就绪后，直接跳到功能 04，到 requestVideoFrameCallback 报告首个呈现帧。原站视频在首页阶段已进行 metadata 预取，因此这里的视频结果是实际导航流程中的等待，不是两个独立、从零开始的视频文件下载测速。

| 指标 | 原版两轮 | 优化后两轮 | 两轮均值变化 |
|---|---|---|---|
| 人仔显示 | 46.664 / 44.961 秒 | 4.843 / 5.600 秒 | 45.81 → 5.22 秒，减少 88.6% |
| 人仔显示前已接收字节 | 9,291,560 / 8,965,033 B | 229,761 / 902,516 B | 减少 93.8% |
| 首屏阶段视频请求 | 1 / 1 次 | 0 / 0 次 | 不再抢占首屏带宽 |
| 功能 04 首帧等待 | 6.524 / 6.679 秒 | 6.316 / 2.677 秒 | 6.60 → 4.50 秒，减少 31.9% |

视频仍有明显波动：首轮接近原版，第二轮缩短较多。样本仅两轮，用于验证资源体积和调度改动的方向，不据此承诺所有网络环境都能秒开。两轮测试均确认视频解码分辨率为 1280×720。

原始结果见 [media-performance-results.json](media-performance-results.json)。`scripts/benchmark-media.cjs` 使用 Playwright；可通过 `PLAYWRIGHT_MODULE` 指定已安装的模块路径。运行前在 `.cache/perf-before.html`、`.cache/perf-before-pet.js` 放入优化前快照（可从 `988ae6d` 提取）。脚本启动两个隔离的本地测试端口并输出新的结果到 `.cache/media-performance.json`。

此外检查了 MP4 moov 在 mdat 之前、字节范围请求 206、资源 MIME、首屏视频/图集未加载、截图进入视口加载、视频播放/暂停/续播/离屏暂停，以及桌宠悬停和拖拽。页面布局和动效设计保持不变。
